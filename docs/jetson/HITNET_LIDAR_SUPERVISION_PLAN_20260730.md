# HITNet 真机激光雷达监督与微调方案

日期：2026-07-30

## 可行性结论

可以使用临时安装的三维激光雷达为四组虚拟双目生成真机参考视差，
用于诊断和微调 HITNet。

激光雷达不需要与相机光心重合，但必须：

1. 与四相机刚性安装并同时采集；
2. 标定 LiDAR 到相机/IMU 参考系的六自由度外参；
3. 同步时间戳；
4. 正确处理遮挡、视野、运动畸变和稀疏标签；
5. 把 LiDAR 点变换后的轴向深度 Z 转换为视差，而不是直接使用量测距离。

若是把相机和雷达先后放到“差不多相同的位置”分别采集，只有完全静态场景
和高精度重复定位时才勉强适合诊断，不适合生成高质量训练标签。

## 当前 HITNet 模型状态

本机当前模型输入输出：

```text
输入：float32 [1, 2, 240, 320]
输出：float32 [1, 240, 320, 1]
输入内容：归一化到 0–1 的左、右灰度矫正图
输出内容：像素视差
```

ONNX 二进制元数据表明它由 `tf2onnx` 转换，源文件来自：

```text
.../tools-NNModels-generator/HITNET/
hitnet_saved_model_1x240x320/model_float32.tflite
```

当前 Jetson 仓库只有 ONNX/TRT 模型和推理代码，没有原始训练工程、优化器状态
或可继续训练的 checkpoint。不能直接把优化后的 ONNX/TensorRT plan 当成训练权重。

应优先在原外星人电脑、迁移硬盘和历史源码中寻找：

```text
tools-NNModels-generator/HITNET/
hitnet_saved_model_1x240x320/
checkpoint
saved_model.pb
variables/
train.py
losses.py
```

如果找不到，只能：

- 使用第三方 PyTorch HITNet 实现重新训练并导出；
- 或重新实现与当前 TensorFlow/TFLite 网络等价的训练图；
- 或选择另一个训练和导出链完整的轻量双目网络。

## 雷达选择

为了同时监督四个方向，优先选择：

- 360°水平视场三维雷达；
- 32线以上，64线更好；
- 能提供每点时间戳；
- 支持 PPS/PTP 或稳定 ROS 时间戳；
- 有可靠 ROS1 驱动。

低线数雷达也能使用，但单帧标签会很稀疏，需要在静态场景累计多个扫描。
只有前向视场的固态雷达一次只能监督部分扇区。

## 安装与标定

建议把雷达临时固定在相机组件上方或下方，确保：

- 支架不变形；
- 采集期间不拆装；
- 雷达视野不被机架大面积遮挡；
- 雷达与相机共同覆盖 0.5–10 m 目标范围。

需要求解：

```text
T_imu_lidar
```

或者直接求每个鱼眼/虚拟左相机与雷达的变换。可使用平面板、带反光材料的
相机—雷达联合标定靶，或可靠的目标式/无目标式标定工具。AprilGrid自身只适合
相机检测，不应假设普通黑白打印能被雷达稳定提取。

## 同步采集数据

每个采样时刻至少保存：

```text
/oak_ffc_4p/assemble_image
/lidar/points
/tf 或固定外参
IMU/里程计（移动采集时用于去畸变和运动补偿）
```

优先先采静态数据：

1. 相机与雷达固定不动；
2. 每个场景累计 1–3 秒雷达点；
3. 选择与累计扫描中间时刻接近的相机帧；
4. 只保留静态物体；
5. 更换场景、距离、光照和材质。

静态累计可以显著提高点密度，也避免移动雷达扫描的运动畸变。后续再增加移动
数据，并使用逐点时间戳、IMU或LiDAR里程计去畸变。

## 参考视差生成

对四个扇区分别处理。以某组虚拟左相机为例：

1. 把 LiDAR 点变换到虚拟左相机原始坐标系；
2. 应用该双目的左相机矫正旋转 `R1`；
3. 删除 `Z <= 0` 和不在图像内的点；
4. 使用矫正后的投影矩阵投到 320×240 图像；
5. 同一像素只保留最近表面，执行 z-buffer；
6. 处理相机可见但LiDAR被遮挡/反之的区域；
7. 用轴向深度计算：

```text
d_gt = fx_rectified * baseline / Z_rectified
```

8. 保存 `disparity_gt`、`valid_mask` 和置信度。

注意：

- LiDAR原始量测通常是射线距离 `range`；
- 训练标签必须使用变换到虚拟左相机后的轴向 `Z`；
- 直接用 `fx*B/range` 会在大视场边缘产生系统误差；
- 不要用大范围图像插值把稀疏点伪装成高置信稠密真值。

## 数据集格式

每个样本建议保存：

```text
pair_id/
  left.png
  right.png
  disparity_gt.npy
  valid_mask.png
  confidence.npy
  metadata.yaml
```

metadata至少包括：

```text
sector_id
timestamps
fx
baseline
T_lidar_virtual_left
R1
exposure
scene_id
static_or_moving
```

所有四个扇区都要均衡采样，避免网络只学会标定板和当前办公室。

## 微调损失

LiDAR标签稀疏，因此建议组合：

```text
L = L_sparse_lidar
  + λ1 * L_photometric
  + λ2 * L_left_right
  + λ3 * L_edge_aware_smoothness
```

其中：

- `L_sparse_lidar`：只在有效LiDAR投影像素计算Huber/Smooth-L1；
- 光度损失必须使用遮挡掩码；
- 左右一致性只在共同可见区域计算；
- 平滑项不能跨越明显图像边缘；
- LiDAR置信度低、掠射角大或跨时间运动的点应降权或删除。

如果只能获得少量数据，应微调预训练模型，不建议从零训练。

## 数据规模与划分

建议先做试验集：

```text
20–30个静态场景
每个场景20–50个有效时刻
四个扇区均衡
```

验证投影和训练链正确后，再扩展到至少数千到数万组有效双目样本。

训练、验证、测试必须按“场景”划分，不能随机拆分相邻视频帧，否则会发生严重
数据泄漏。

场景应覆盖：

- 室内/室外；
- 低纹理墙面和地面；
- 细杆、线缆和箱体；
- 玻璃、反光和黑色物体；
- 0.5、1、2、3、5、10 m；
- 暗光、正常光和高动态范围；
- 四个扇区及其重叠区。

## 训练与部署验收

先在外星人电脑训练，Jetson只负责采集和最终推理。

验收顺序：

1. 原始HITNet、微调HITNet在相同测试场景比较；
2. 在LiDAR有效像素计算EPE、Bad-1、Bad-2和深度相对误差；
3. 对平面计算点到平面RMSE；
4. 检查四扇区同一结构的闭环一致性；
5. 导出保持相同输入输出契约的float32 ONNX；
6. 在Jetson生成新的FP16 TensorRT engine；
7. 做离线bag回放；
8. 做30分钟10 Hz在线测试；
9. 旧引擎保留，只有新模型量化验收通过后才替换。

## 最低风险的执行顺序

1. 确定雷达型号、ROS话题、点格式、时间戳与水平/垂直视场；
2. 搜索原外星人电脑是否保留HITNet训练工程/checkpoint；
3. 刚性安装LiDAR并完成联合外参；
4. 只录一个静态场景的小bag；
5. 实现LiDAR到四组虚拟左图的投影；
6. 用参考视差替换网络视差，验证Q重投影点云；
7. 投影链通过后再批量采集；
8. 先做小规模过拟合测试，确认训练损失和标签正确；
9. 扩大数据集并正式微调；
10. 导出ONNX/TRT并进行真机验收。
