# HITNet 四向深度运行时优化记录

日期：2026-08-01

## 目标与边界

目标是在不减少四个双目方向、不启用有效性过滤、不改变标定参数和HITNet权重的前提下，提高Orin Nano上的真实新深度帧率。频率以不同ROS时间戳计数，不把同一结果的重复发布算作新帧。

## 定位结果

- 原页面约3.0 FPS，数据生产端约3.4 Hz。
- 原深度话题表面约10 Hz，但约四条消息共用同一时间戳。
- 单个FP16 HITNet纯TensorRT吞吐为17.24次/秒。
- 四个执行上下文、四CUDA stream无Graph时总吞吐18.98次/秒，即完整四向理论上限约4.75组/秒。
- 四stream使用CUDA Graph的纯引擎吞吐20.61次/秒，即完整四向理论上限约5.15组/秒。
- 当前ONNX固定为`float32 [1,2,240,320] -> float32 [1,240,320,1]`，内部大量Reshape/GatherND及固定batch=1形状，不能安全地只修改输入维度做batch=4。
- 当前模型没有Q/DQ或QLinear算子，不是现成的INT8 QAT模型。

## 已实施优化

1. 修复`output_ready_`从不清零的问题：每份视差只做一次重投影和发布，不再以10 Hz重复构造旧点云。
2. 增加`input_ready_`握手：每组校正图只运行一次HITNet，不再重复推理上一帧。
3. 四个TensorRT执行上下文使用非阻塞CUDA stream。
4. 节点初始化阶段预热并捕获四个CUDA Graph；运行阶段执行固定的H2D、TensorRT、D2H图。
5. 将两级320×240几何remap移至CPU，与GPU HITNet并行，避免在已饱和GPU上争抢；正式配置增加`use_cuda_rectification: false`。
6. 发布检查提高到100 Hz，但仍由`output_ready_`事件门控，因此不会重复发布。
7. 增加预处理、四路推理和发布阶段的节流耗时日志。

## 最终实测

优化后的典型耗时：

```text
四组去畸变/校正及输入准备：约21～45 ms
四组HITNet及输出拷贝：约197～213 ms（随系统负载波动）
四组深度/点云发布：约7～10 ms
```

最终15秒基准：

```text
消息数：73
不同时间戳：73
真实新深度：4.862 Hz
源时间戳间隔中位数：200.1 ms
```

动态骨架页面实测约4～5 FPS，RTMPose TensorRT本身不是瓶颈。图像、深度和三维骨架输出在优化后保持正常。

## 为什么当前不能仅靠运行时修改达到10 Hz

10 Hz完整四向深度要求每秒完成40次双目HITNet推理。当前FP16 engine在Nano上的纯推理总吞吐约20～25次双目/秒，GPU已接近满载。线程、异步拷贝、CUDA Graph、CPU/GPU流水已经无法补足约1.6～2倍的算力缺口。

不建议通过伪造10 Hz、重复旧深度、只计算有人扇区或轮流漏算方向来宣称达到目标。

## 达到真实10 Hz的下一条可行路线

保留当前FP16 engine作为回退基线，另建INT8候选：

1. 采集覆盖室内、室外、明暗、近远距离的真实四组校正双目输入；
2. 对HITNet进行量化感知训练或至少使用真实输入做EntropyCalibrator2；
3. 生成独立INT8 engine，不覆盖FP16文件；
4. 对同一批输入逐像素比较FP16/INT8视差，包括中位误差、P95误差、坏点比例和深度误差；
5. 只有总吞吐达到至少40双目对/秒且质量阈值通过，才切换正式配置。

若INT8仍不足，必须重新导出适合batch=4或经过蒸馏/剪枝的HITNet，而不是继续调整ROS发布频率。
